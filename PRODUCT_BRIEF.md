# PRODUCT BRIEF — Telegram-канал о Дубае и недвижимости ОАЭ

> Это единый источник правды для всех агентов проекта. Любое решение, противоречащее
> этому файлу, считается ошибкой. Если бриф требует изменения — сначала правим бриф.

## 1. Бизнес-цель владельца канала

Владелец — частный специалист по недвижимости в Дубае (женщина, личный бренд, местоимения they/them
в англоязычных артефактах). Канал решает четыре задачи, в порядке приоритета:

1. **Ежедневные контакты.** Подписчик должен открывать канал каждый день — значит нужен
   регулярный, полезный и не только-про-недвижимость контент.
2. **Лояльность к специалисту.** Подписчик должен воспринимать автора как эксперта и человека,
   а не как ленту объявлений. Отсюда обязательная доля личных постов.
3. **Знакомство с новыми проектами.** Регулярный, но не навязчивый поток новостей застройщиков
   и новых лончей.
4. **Сбор контактов на лончи.** Ключевая конверсия: подписчик оставляет заявку на конкретный
   предстоящий запуск проекта.

**Главная метрика:** число заявок-интересантов на лончи в месяц.
**Вспомогательные:** ER (реакции+комментарии / просмотры), дневной охват, прирост подписчиков,
доля постов с досмотром до CTA.

## 2. Зафиксированные решения (подтверждены владельцем)

| Параметр | Решение |
|---|---|
| Язык | Русский |
| ЦА | Смешанная: инвесторы из СНГ + русскоязычные резиденты ОАЭ |
| Публикация | Python + GitHub Actions, **с ручным подтверждением** через Telegram-кнопки |
| Изображения | Приоритет — фирменные шаблоны-карточки (генерация кодом); фолбэк — стоки Unsplash/Pexels |
| LLM | Anthropic API (основной, тексты), OpenAI API (доступен; опционально изображения) |
| Публикация в канал | Telegram Bot API, бот — админ канала |
| Личные посты владельца | ~2 в неделю, пишет сама по подготовленным брифам |
| Часовой пояс | Asia/Dubai (UTC+4). Все cron в GitHub Actions задаются в UTC |

## 3. Архитектура пайплайна (обязательный контур)

```
[1 COLLECT]  источники (RSS/API/HTML/события) → сырые items
      ↓
[2 NORMALIZE + DEDUPE]  единая схема, хэш-дедупликация, хранение в state/
      ↓
[3 SCORE]  релевантность для ЦА, свежесть, рубрика → отбор топ-N
      ↓
[4 GENERATE]  Claude пишет пост по шаблону рубрики + tone of voice + факт-чек-гейт
      ↓
[5 ILLUSTRATE]  фирменная карточка (Pillow) или сток → image
      ↓
[6 QUEUE]  пост кладётся в очередь с предложенным слотом публикации
      ↓
[7 APPROVE]  бот шлёт владельцу превью в личку: [Опубликовать] [Переписать] [Отклонить] [Отложить]
      ↓
[8 PUBLISH]  по расписанию публикуется одобренное, с учётом слотов
      ↓
[9 ANALYTICS]  сбор просмотров/реакций, недельный отчёт, обратная связь в SCORE
```

### Жёсткие технические ограничения

- **Состояние хранится в репозитории** (JSON/YAML в `state/`), коммитится ботом.
  Никакой внешней БД — GitHub Actions stateless, а репо даёт бесплатный аудит и историю.
- **Апрув-кнопки** реализуются через `getUpdates` long-poll в короткоживущем workflow
  (webhook невозможен без постоянного хоста). Учитывать, что `getUpdates` и webhook
  взаимоисключающи, и offset надо персистить.
- **Лимиты Telegram:** caption у медиа — 1024 символа, обычное сообщение — 4096.
  Посты длиннее 1024 публикуются как фото + отдельный текст либо укорачиваются на этапе GENERATE.
- **Секреты только через GitHub Secrets.** Никаких ключей в коде, логах или коммитах.
- **Идемпотентность:** повторный запуск workflow не должен приводить к дублю публикации.
  Обязателен ключ дедупликации на уровне опубликованных постов.
- **Rate limits:** ~20 сообщений/мин в один чат у Bot API; ретраи с экспоненциальной паузой.
- **Сухой прогон:** `DRY_RUN=1` должен прогонять весь пайплайн без единого обращения в Telegram.
- **Стоимость:** пайплайн должен укладываться в бесплатный тариф GitHub Actions
  (публичный репо — безлимит; приватный — 2000 мин/мес). Считать бюджет в отчёте.

## 4. Контент: обязательные требования

- **Рубрикатор** минимум на 8–10 рубрик, покрывающих три пласта: недвижимость/инвестиции,
  жизнь в Дубае (события, сервисы, законы, лайфхаки), личное/экспертное.
- **Доля продающего контента** — не более ~20–25% ленты. Остальное — польза.
- **Недельная сетка:** 1–2 поста в день, из них ~2 в неделю — личные посты владельца.
- **Личные посты:** агент готовит не текст, а **бриф-заготовку** (тема, структура, 3 вопроса
  владельцу, пример first line) — владелец пишет сама.
- **Анти-галлюцинации:** любая цифра (цена, доходность, срок, дата события) в посте обязана
  иметь источник из собранных данных. Пост без подтверждённого источника цифры — в брак.
- **Tone of voice** оформляется отдельным файлом и подаётся в промпт.
- **Лид-магниты и CTA** под цель №4: механика сбора контактов на лончи (waitlist).

## 5. Источники данных — что искать

Нужен реестр источников с полями: название, URL, тип (RSS/API/HTML/Telegram/календарь),
рубрика, частота обновления, язык, надёжность, юридические ограничения на перепечатку.

Категории для покрытия:
- Новости недвижимости ОАЭ и профильные издания;
- Официальные данные и регуляторы (транзакции, индексы, правила);
- Застройщики (пресс-релизы, лончи);
- Городские/государственные новости ОАЭ (визы, законы, транспорт, тарифы);
- Афиша и крупные события Дубая (концерты, спорт, выставки, сезонные фестивали);
- Лайфстайл/сервисы/лайфхаки для резидентов.

Каждый источник **обязан быть проверен на доступность** (реальный HTTP-запрос) и помечен
статусом. Непроверенные источники в реестр не попадают.

## 6. Правовые и этические рамки

- Новости — пересказ своими словами + ссылка на первоисточник. Никакого копипаста.
- Изображения — только с правом использования (собственные карточки, Unsplash/Pexels лицензия,
  официальные пресс-материалы застройщика). Фиксировать источник и лицензию у каждой картинки.
- Никаких обещаний доходности как гарантии; инвестиционные формулировки — аккуратные.
- Персональные данные интересантов — минимально необходимые, не хранить в открытом репозитории.

## 7. Определение готовности (Definition of Done)

Проект считается сданным, когда:

1. `python -m pipeline.run --dry-run` проходит end-to-end и выдаёт готовый пост + картинку локально.
2. Реестр источников заполнен, каждый источник проверен HTTP-запросом, статус зафиксирован.
3. Контент-стратегия, рубрикатор, tone of voice, сетка на 4 недели — в `docs/`.
4. GitHub Actions workflows описаны и валидны по синтаксису.
5. `docs/SETUP.md` даёт пошаговый запуск с нуля для человека без опыта разработки.
6. Тесты на критичную логику (дедуп, лимиты Telegram, идемпотентность) проходят.
7. Все секреты — только из окружения; поиск по репо не находит ключей.
