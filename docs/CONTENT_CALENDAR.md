# Контент-календарь: 4 недели

Часовой пояс всех значений — **Asia/Dubai (UTC+4)**.
Опорная дата старта цикла: понедельник **21.09.2026**.

Числа в этой сетке совпадают с плановыми частотами в `pipeline/config.py`
(поле `per_4weeks`) и с расчётом в [`CONTENT_STRATEGY.md`](CONTENT_STRATEGY.md).
Если меняете сетку — меняйте и конфиг, иначе тест
`tests/test_prompts_rubrics.py` покажет расхождение.

Логика слотов:

- **Утро 09:00–09:30** — «полезное»: цифры, деньги, правила. Дубай едет на
  работу, Москва (UTC+3) — 08:00–08:30.
- **Обед 12:30** — только пятница, афиша выходных.
- **Вечер 19:30–20:00** — «читаемое»: лончи, районы, быт. Прайм и для ОАЭ,
  и для СНГ.
- **Суббота 11:00** — личное, неспешное чтение.
- **Воскресенье 19:00** — закрывающий слот недели.

Автоматические слоты публикации в коде — `09:30` и `19:30`
(`pipeline/postqueue.py::SLOTS`). Остальные времена в сетке — для постов,
которые владелица ставит вручную, и для будущего расширения списка слотов.

Тип изображения: **К** — фирменная карточка, **С** — сток, **П** —
пресс-материал застройщика, **Ф** — живое фото владельца.

Проверка суммы: 8 + 6 + 6 + 6 + 5 + 4 + 4 + 4 + 4 + 2 = **49**.
Колонка «в конфиге» совпадает с фактической по всем десяти строкам.

### Проверка обязательных ограничений

**1. Постов в день.** Понедельник–пятница по 2, суббота 1 (в неделе 2 — две),
воскресенье 1.

```
49 постов / 28 дней = 1,75 поста в день
Требование брифа: 1–2 в день   ->   1,75 в диапазоне   OK
Максимум в один день: 2         ->   потолок не нарушен OK
```

**2. Личные посты.** Ровно 2 в каждую неделю (четверг утром и суббота днём).

```
2 × 4 = 8 за цикл   OK
```

**3. Доля продающего контента.** Считаем по широкому определению, которое
зашито в код (`SELLING_RUBRICS`): `new_launch` + `investor_math` + `case_story`.

```
new_launch    = 6
investor_math = 4
case_story    = 2
Продающих     = 6 + 4 + 2 = 12
Всего постов  = 49
Доля = 12 / 49 = 0,2449 = 24,5%
Лимит по брифу = 25%   ->   24,5% <= 25%   OK
Запас: 0,25 × 49 = 12,25 поста; 12,25 − 12 = 0,25 поста
```

Запас до потолка — четверть поста, то есть его практически нет.
Один внеплановый лонч в цикл добавить **нельзя** без вытеснения: чтобы взять
дополнительный `new_launch`, нужно убрать один `investor_math` или
`case_story`, либо добавить 4 непродающих поста.

По узкому определению (только прямое продвижение объекта и услуги —
`new_launch` и `case_story`) доля составляет `8 / 49 = 16,3%`.

**4. Разброс по неделям.** Пиковые недели 1 и 3 дают 33,3%, недели 2 и 4 —
15,4% и 16,7%. Ограничение брифа относится к циклу целиком, но два пика подряд
недопустимы: между ними всегда стоит «лёгкая» неделя.

**5. Два продающих поста подряд по ленте.** Между `new_launch` понедельника
и следующим продающим постом всегда не менее двух непродающих. Единственная
узкая точка — недели 1 и 3, где пятничный `new_launch` и воскресный
`case_story` разделены одним личным постом субботы. **Этот пункт под ручным
контролем:** при добавлении внепланового лонча в пятницу `case_story`
воскресенья переносится на следующую неделю.

### Правила замены слота

- Нет официальной фактуры на лонч — слот занимает `faq_answer` или `area_guide`.
  Пост `new_launch` без подтверждённых цены и даты не пишется вовсе: его
  остановит факт-чек-гейт.
- Крупное событие города (источник `events`) разово усиливает пятничный слот
  `events_afisha`, а пятничный `new_launch` сдвигается на субботу 19:30.
- **Личный пост не заменяется генерацией.** Если владелица не написала, слот
  остаётся пустым или закрывается `dubai_life`. Второй личный пост недели
  при этом обязателен.
- Слот, освободившийся из-за брака на факт-чек-гейте, закрывается рубрикой
  того же слоя пирамиды, а не продающей.
