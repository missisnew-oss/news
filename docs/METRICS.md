# Справочник метрик

Ориентиры рассчитаны для нового русскоязычного нишевого канала (старт с нуля,
органика плюс личный трафик владелицы). «На старте» = первые 4–6 недель.
«Через 3 месяца» = 12–14 недель, ожидаемый размер канала 800–2000 подписчиков.

Ориентиры — это гипотезы для сверки, а не обещания. Через месяц реальных данных
их надо пересмотреть под фактический канал.

---

## 1. Заявки на лончи (главная метрика)

* **Определение.** Число обезличенных записей в `state/leads.json` со статусом
  не ниже `new`, созданных в календарном месяце, с указанием интереса к
  конкретному лончу или проекту.
* **Формула.** `leads_month = Σ leads[] where created_date in month`
* **Источник.** `state/leads.json` → `counters.by_month`. Первичный ввод:
  `/start <payload>` у бота (автоматически, когда deep-link будет реализован)
  плюс ручная отметка владелицей заявок из личных сообщений.
* **Ориентир.** Старт: 3–5 в месяц. Через 3 месяца: 10–15 в месяц.
* **Если проседает.** Проверять по порядку: (1) есть ли CTA в постах вообще
  (доля постов с CTA не ниже 40%); (2) работает ли deep-link — сделать тестовый
  клик; (3) какая рубрика даёт заявки по `counters.by_rubric` — поднять её вес
  вручную, не дожидаясь месячного пересчёта; (4) не упал ли охват (метрика 4);
  (5) слишком мягкий CTA — заменить «пишите, если интересно» на конкретное
  действие с выгодой («пришлю PDF с планировками и платёжным планом»).

## 2. CR поста в заявку

* **Определение.** Доля просмотров поста, превратившихся в заявку.
* **Формула.** `CR_post = leads_attributed / views × 100%`.
  Вспомогательные: `CTR = cta_clicks / views × 100%`,
  `CR_click→lead = leads_attributed / cta_clicks × 100%`.
* **Источник.** `views` — ручной ввод (Bot API просмотров не даёт),
  `cta_clicks` и `leads_attributed` — автоматически.
* **Ориентир.** `CR_post`: старт 0,2–0,5%, через 3 месяца 0,5–1,0% для
  продающих рубрик. `CTR`: старт 0,8–1,5%, через 3 месяца 1,5–3%.
  `CR_click→lead`: 15–30% стабильно.
* **Если проседает.** Разделить диагноз. Низкий CTR = проблема в самом посте
  (CTA не дочитали, кнопки нет, оффер неясен) → короче текст, кнопка вместо
  текстовой ссылки, конкретика в оффере. Низкий `CR_click→lead` при нормальном
  CTR = проблема в боте: ломается сценарий после `/start`, слишком много
  вопросов, нет мгновенной ценности → отдавать обещанное сразу первым
  сообщением, спрашивать контакт вторым.

## 3. ER (Engagement Rate)

* **Определение.** Доля аудитории, совершившей видимое действие.
* **Формула.**
  `ER_views = (реакции + комментарии + пересылки) / просмотры × 100%`
  `ERS = (реакции + комментарии) / подписчики_на_дату_публикации × 100%` —
  автоматический прокси, когда просмотров нет.
* **Источник.** Реакции — апдейт `message_reaction_count`; комментарии —
  сообщения в привязанной группе по `message_thread_id`; пересылки и
  просмотры — только руками.
* **Ориентир.** `ER_views`: старт 6–12% (малый канал всегда выше), через
  3 месяца 4–7% — снижение при росте канала нормально.
  `ERS`: старт 2–4%, через 3 месяца 2–3%.
* **Если проседает.** Проверить формат: длинные тексты без структуры и без
  вопроса в конце не собирают реакций. Добавить один вопрос в конце поста,
  включить в канале набор реакций, разбить полотно на абзацы, вернуть карточки.
  Если падает одновременно с долей включённых уведомлений — это усталость:
  снизить частоту и долю продающего.

## 4. Охват (дневной и на пост)

* **Определение.** Сколько просмотров собирает пост и канал за сутки.
* **Формула.** `Reach_post% = views / subscribers × 100%`; дневной охват =
  сумма просмотров постов за сутки (оговорка: один человек мог посмотреть
  несколько постов, это не уникальные люди).
* **Источник.** Только приложение Telegram, ручной ввод.
* **Ориентир.** `Reach_post%`: старт 50–80% (у малого канала почти все видят),
  через 3 месяца 30–50%. Падение ниже 25% — тревога.
* **Если проседает.** Время публикации (для аудитории в СНГ и ОАЭ рабочее
  окно — 09:00–11:00 и 19:00–21:00 Asia/Dubai), частота (больше 2 постов в день
  режет охват каждого), первые 3 строки поста (в превью уведомления видно
  только их), доля отключённых уведомлений. Внешний импульс: репосты из
  личного блога или сторис.

## 5. Прирост подписчиков

* **Определение.** Нетто-изменение числа подписчиков за период.
* **Формула.** `Net_new = subs_end − subs_start`;
  `Growth% = Net_new / subs_start × 100%`.
* **Источник.** `getChatMemberCount` раз в сутки → `state/analytics.json`.
  Отписки отдельно — только из приложения.
* **Ориентир.** Старт: +15–25% в месяц (низкая база, проценты легко большие;
  в абсолюте +50–150 человек). Через 3 месяца: +8–12% в месяц органически.
* **Если проседает.** Органика в Telegram почти не работает сама: нужен внешний
  источник. Проверить, что ссылка на канал есть во всех личных профилях;
  договориться о 1–2 взаимных репостах в месяц; сделать «якорный» пост-гайд,
  который хочется переслать. Если растёт, но падает охват — пришла нецелевая
  аудитория, проверить источник подписок.

## 6. Доля продающего контента

* **Определение.** Доля постов рубрик `new_launch`, `investor_math`,
  `case_story` в общем числе постов периода.
* **Формула.** `Selling% = постов_продающих / всего_постов × 100%`
* **Источник.** `state/analytics.json`, окно 28 дней.
* **Ориентир.** **Потолок по брифу — 25%.** Старт: 20%. Устойчивое рабочее
  значение: 20–25%. Выше 25% — нарушение продуктового ограничения, а не
  «допустимый риск».
* **Если превышает.** Отписки и падение ER — прямое следствие. Ограничение
  зашито в SCORE (см. `docs/ANALYTICS.md`, §5.3) и в тест
  `tests/test_prompts_rubrics.py`. Разбавить `rules_and_laws`, `area_guide`,
  `faq_answer`. Если проседает ниже 15% — заявок не будет, поднять вес
  `new_launch`.

## 7. Доля постов с подтверждёнными источниками

* **Определение.** Доля опубликованных постов, у которых `source_ids` непусты
  и каждый источник есть во входных материалах.
* **Формула.** `Sourced% = постов с минимум одним валидным source_id / всего × 100%`
* **Источник.** `state/analytics.json` → `posts[].source_ids`.
* **Ориентир.** Для фактологических рубрик (`market_pulse`, `new_launch`,
  `rules_and_laws`, `investor_math`) — старт не ниже 95%, через 3 месяца 100%.
  Для `personal` и `dubai_life` источники не требуются, они в знаменатель
  не входят.
* **Если проседает.** Это отказ, а не метрика: пост без источника в
  фактологической рубрике не должен публиковаться. Падение = дыра в
  факт-чек-гейте, чинить гейт, а не метрику. Проверить, не отвалился ли
  RSS-фид: пустая выдача заставляет модель додумывать.

## 8. Доля брака на факт-чек-гейте

* **Определение.** Доля сгенерированных черновиков, отклонённых автоматическим
  гейтом (нет источника, цифра не подтверждается, запрещённая формулировка).
* **Формула.** `Reject% = черновиков_отклонено / черновиков_сгенерировано × 100%`
* **Источник.** Лог пайплайна и `gate` в `out/drafts.json`.
* **Ориентир.** Старт: не выше 20–25% (промпты сырые).
  Через 3 месяца: не выше 8–10%.
* **Если растёт.** Разобрать 5 последних отклонений по причинам. Типовые:
  (1) модель выдумывает точные цифры — усилить запрет в `prompts/system_tone.md`;
  (2) источник устарел — сузить окно свежести; (3) запрещённые формулировки —
  расширить стоп-лист из `docs/LEGAL.md` прямо в промпт.
  Рост брака выше 40% обычно означает смену формата у источника, а не
  деградацию модели.

## 9. Доля постов, одобренных с первого раза

* **Определение.** Доля постов, которые владелица одобрила без правок и без
  повторной генерации.
* **Формула.** `ApprovedFirst% = постов с approved_first_try / отправленных на апрув × 100%`
* **Источник.** `state/queue.json` → `approval.action`.
* **Ориентир.** Старт: не ниже 55–60%. Через 3 месяца: не ниже 85%.
* **Если проседает.** Это метрика качества промптов, а не владелицы. Собрать
  5 последних отклонённых, выделить повторяющуюся причину (тон, длина, неверный
  акцент, неуместный CTA) и внести правку в промпт конкретной рубрики, а не в
  общий. Если отклоняется одна рубрика — правится одна рубрика. Косвенный
  индикатор — время от отправки на апрув до решения: рост времени означает,
  что владелица каждый раз переписывает.

## 10. Вспомогательные (смотреть, но не оптимизировать)

| Метрика | Формула | Ориентир 3 мес |
|---|---|---|
| Доля постов с досмотром до CTA (прокси) | `cta_clicks / views` относительно медианы канала | не ниже 0,7 медианы |
| Доля постов с CTA | `постов с CTA / всего` | 40–50% |
| Комментарии на пост | `Σ comments / постов` | не ниже 1,5 |
| Доля подписчиков с уведомлениями | из приложения | не ниже 65% |
| Время до апрува | медиана `decided_at − sent_at` | не больше 4 часов |
| Доля постов с изображением | `постов с фото / всего` | 60–80% |
