# Запуск с нуля — пошагово

Инструкция рассчитана на человека **без опыта разработки**. Делайте по порядку,
ничего не пропуская. Весь путь занимает примерно полтора часа.

Если что-то пошло не так — в конце есть раздел «Если не работает».

---

## Что в итоге получится

Робот каждый день собирает новости о Дубае и недвижимости, пишет из них посты,
рисует к ним картинки и **присылает вам в личку на утверждение**. Вы нажимаете
«Опубликовать» — и в назначенное время пост выходит в канале. Без вашего
нажатия в канал не попадает ничего.

## Шаг 1. Что нужно подготовить заранее

1. Аккаунт на **GitHub** — https://github.com (бесплатно).
2. **Telegram** на телефоне или компьютере.
3. **Канал в Telegram** — уже создан.
4. Ключ **Anthropic API** — https://console.anthropic.com → API Keys → Create Key.
   Ключ выглядит как `sk-ant-...`. Скопируйте и сохраните: показывают один раз.
   Это платно, но недорого: 2 поста в день — единицы долларов в месяц.

Необязательно, но улучшает картинки:
5. Ключ **Unsplash** — https://unsplash.com/developers (бесплатно) или
   **Pexels** — https://www.pexels.com/api/ (бесплатно). С ними карточки
   рисуются поверх настоящих фотографий Дубая.
6. Ключ **OpenAI** — https://platform.openai.com/api-keys (платно): бот сам
   генерирует яркий фон под каждый пост моделью `gpt-image-1`. Ориентир по
   цене — около $0.04–0.07 за картинку в качестве `medium` (примерно $3–5 в
   месяц при двух постах в день; `high` — в 3–4 раза дороже). Качество и
   рубрики-исключения задаются в `assets/brand.yml → ai_image`.
   Порядок выбора фото: пресс-фото застройщика → OpenAI → Unsplash/Pexels →
   собственная градиентная карточка. Без ключей всё работает.

**Картинка по умолчанию — светлая компактная карточка** (1200×630, без
фото и без расходов). Она включена в `assets/brand.yml → card.style: light`;
цвета — в блоке `light:` того же файла. Фото-карточки (Whitewill/Ruble)
остаются как запасной стиль: `card.style: photo` или `editorial`.

**Логотип.** Пока на карточках стоит надпись `REALNEW MARY` (меняется в
`assets/brand.yml → name`). Чтобы поставить настоящий логотип, положите в
репозиторий файл `assets/logo-dark.png` — PNG с прозрачным фоном, тёмный
рисунок высотой от 200 px (для светлой карточки); путь можно поменять в
`brand.yml → light.logo_path`. Для фото-карточек нужен светлый (белый)
вариант `assets/logo.png` (`brand.yml → logo_path`). Там же — цвета, теги рубрик («#НОВОСТЬДНЯ», «#ЛОТНЕДЕЛИ»), формат
(4:5 или 16:9) и шрифт: для вида «как у Whitewill» положите в `assets/fonts/`
свободный жирный шрифт с кириллицей (Montserrat ExtraBold или Inter Bold с
fonts.google.com, лицензия OFL) и укажите его в `brand.yml → fonts.bold`.

## Шаг 2. Создаём бота у @BotFather

1. Откройте Telegram и найдите **@BotFather** (с синей галочкой).
2. Нажмите «Start» (или отправьте `/start`).
3. Отправьте `/newbot`.
4. BotFather спросит имя бота — это то, что увидят люди. Например:
   `Дубай • новости и недвижимость`.
5. Потом спросит username — должен быть уникальным и заканчиваться на `bot`.
   Например: `maria_dubai_news_bot`.
6. BotFather пришлёт сообщение со строкой вида:

   ```
   1234567890:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw
   ```

   **Это токен бота.** Сохраните его в заметки. Никому не показывайте:
   кто знает токен — управляет ботом.

7. Сразу выключите боту режим групп, чтобы его не добавляли куда попало:
   отправьте `/setjoingroups` → выберите своего бота → `Disable`.

## Шаг 3. Делаем бота администратором канала

1. Откройте свой канал в Telegram.
2. Название канала сверху → **Управление каналом** → **Администраторы** →
   **Добавить администратора**.
3. Найдите своего бота по username (`@maria_dubai_news_bot`) и выберите его.
4. Включите права:
   - **Публикация сообщений** — обязательно;
   - **Редактирование сообщений** — обязательно;
   - **Удаление сообщений** — желательно.

   Всё остальное (добавление участников, управление видео-чатами, назначение
   администраторов) **выключите**. Чем меньше прав, тем безопаснее.
5. Сохраните.

## Шаг 4. Узнаём ID канала и свой ID

Оба значения нужны боту, чтобы понимать, куда публиковать и кого слушать.

### Свой user_id

Самый надёжный способ — спросить у **своего** бота (после шага 8, когда он
уже запущен): напишите ему в личку `/id`, он ответит «Ваш ID: 123456789».

Пока бот не запущен: найдите в Telegram бота **@userinfobot**, нажмите
«Start» — он ответит числом в поле `Id`, например `123456789`.
**Это ваш `TELEGRAM_OWNER_ID`.** Только этот человек сможет нажимать
кнопки утверждения.

> Частая ошибка: в секрет попадает **ID бота**, а не ваш. Тогда в журнале
> будет «the bot can't send messages to the bot». Напишите своему боту `/id`
> и вставьте число из его ответа.

### ID канала

Канал, куда публикуем, уже прописан в `config/settings.yml`: **`@realnew_mary`**.
Секрет `TELEGRAM_CHANNEL_ID` заводить не нужно — только если захотите
временно публиковать в другой (например, тестовый) канал.

**Если когда-нибудь понадобится другой публичный канал** (`t.me/maria_dubai`):
`TELEGRAM_CHANNEL_ID` = `@maria_dubai`.

**Если канал назначения приватный:**

1. Напишите своему боту в личку любое сообщение (например, `привет`) —
   без этого он не сможет вам отвечать.
2. Перешлите **любой пост из канала** боту @userinfobot.
3. Он покажет `Forwarded from chat Id:` с числом вида `-1001234567890`.
   **Это ваш `TELEGRAM_CHANNEL_ID`**, вместе с минусом и всеми цифрами.

> Обязательно напишите своему боту `/start` в личку. Telegram не разрешает боту
> писать первым: пока вы не начали диалог, превью на утверждение не придут.

## Шаг 5. Копируем проект себе на GitHub

1. Зайдите на GitHub и откройте страницу этого репозитория.
2. Нажмите **Fork** (справа сверху) → **Create fork**. Теперь копия ваша.
3. Решите, публичный он или приватный:
   - **публичный** — GitHub Actions бесплатны без ограничений (рекомендуется);
   - **приватный** — 2000 бесплатных минут в месяц, а расписание по
     умолчанию съедает около 3600. Его **обязательно** нужно проредить,
     иначе в середине месяца бот молча остановится. Как именно —
     в `docs/ARCHITECTURE.md`, раздел «Расписание и бюджет».

   В обоих случаях секретов в репозитории нет — они хранятся отдельно.

4. В своей копии откройте **Settings → Actions → General** и убедитесь,
   что в разделе *Workflow permissions* выбрано
   **Read and write permissions** — без этого бот не сможет сохранять состояние.

## Шаг 6. Прописываем ключи в GitHub Secrets

Секреты — это сейф GitHub. Никогда не пишите ключи прямо в файлы.

В своей копии репозитория: **Settings → Secrets and variables → Actions →
вкладка Secrets → New repository secret**. Добавьте по одному:

| Имя (скопируйте точно) | Значение | Обязателен |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 2 | да |
| `TELEGRAM_OWNER_ID` | ваш числовой id из шага 4 | да |
| `ANTHROPIC_API_KEY` | ключ `sk-ant-...` | да |
| `TELEGRAM_CHANNEL_ID` | только чтобы переопределить `@realnew_mary` из `config/settings.yml` | нет |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION` | чтение приватных каналов-источников, см. шаг 7а | нет |
| `UNSPLASH_ACCESS_KEY` | ключ Unsplash | нет |
| `PEXELS_API_KEY` | ключ Pexels | нет |
| `OPENAI_API_KEY` | ключ OpenAI — генерация фонов для карточек (`gpt-image-1`), а также `LLM_PROVIDER=openai` | нет |

Там же на вкладке **Variables** (не Secrets) можно при желании добавить:

| Имя | Значение по умолчанию | Зачем |
|---|---|---|
| `LLM_MODEL` | `claude-opus-5` | сменить модель |
| `LLM_PROVIDER` | `anthropic` | переключиться на `openai` |

## Шаг 7. Проверяем источники новостей

**Это обязательный шаг.** Реестр `config/sources.yml` составлен без доступа в
интернет, поэтому робот не знает, какие адреса живые. Пока проверка не
пройдёт хотя бы раз, ему неоткуда брать новости.

1. В своей копии репозитория откройте вкладку **Actions**.
2. Если GitHub спросит подтверждение — нажмите
   «I understand my workflows, go ahead and enable them».
3. Слева выберите **Verify Sources** → справа **Run workflow** → **Run workflow**.
4. Подождите 2–5 минут, обновите страницу. Зелёная галочка — готово.

Больше ничего делать не нужно: робот сам записал результат в
`state/sources_health.json` и с этого момента берёт новости только из
источников, которые реально ответили. Раз в неделю (по воскресеньям) он
перепроверяет всё сам — сломавшийся источник отвалится, оживший вернётся.

> Если какой-то источник хотите выключить навсегда (например, чужой канал
> стал неинтересен) — поставьте ему `enabled: false` в `config/sources.yml`.
> Включать руками ничего не надо.

### Telegram-каналы

В реестре есть восемь Telegram-каналов (`type: telegram`, id начинаются с `tg_`).
Они читаются через публичное веб-превью `t.me/s/…` — логин не нужен, отдельных
ключей заводить не надо, та же проверка **Verify Sources** покроет и их.
Если у канала в `verification.note` написано «страница без постов» — у него
выключено веб-превью или он приватный; через `t.me/s` такой канал прочитать
нельзя. Как добавить ещё канал — `docs/SOURCES.md`, раздел 7.

## Шаг 7а. Приватные каналы-источники (по желанию)

Приватный канал (ссылка вида `t.me/+…`) ни бот, ни веб-превью прочитать не
могут. Его читает **обычный аккаунт Telegram**, который в этом канале состоит.
Делается один раз, на своём компьютере — не в GitHub.

> **Сначала про безопасность.** На выходе получится строка `TELEGRAM_SESSION` —
> это полный вход в аккаунт, как будто кто-то залогинился с вашего телефона.
> Поэтому: (1) она хранится только в GitHub Secrets и никогда не пишется в файлы;
> (2) лучше завести **отдельный аккаунт на другой сим-карте**, подписать его на
> нужные приватные каналы и читать от его имени — тогда утечка секрета не
> затронет ваш личный Telegram. Если появится подозрение на утечку —
> Telegram → Настройки → Устройства → завершить этот сеанс, и секрет мёртв.

1. Аккаунтом, от имени которого будем читать, вступите в приватный канал по
   ссылке-приглашению — в обычном приложении Telegram.
2. Зайдите на https://my.telegram.org → **API development tools**, создайте
   приложение (название любое). Запишите `api_id` (число) и `api_hash` (строка).
3. На компьютере с Python (см. раздел «Запуск на своём компьютере») выполните:

   ```bash
   pip install telethon
   python scripts/telegram_login.py
   ```

   Скрипт спросит `api_id`, `api_hash`, номер телефона и код из Telegram
   (и пароль двухэтапной защиты, если включён). Ничего на диск он не пишет.
4. Он напечатает две вещи:
   - строку между `=== TELEGRAM_SESSION ===` — заведите три секрета
     `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION` (шаг 6);
   - список каналов аккаунта с числовым `channel_id`. Найдите нужный приватный
     канал и скопируйте число.
5. Откройте `config/sources.yml`, найдите запись `tg_private_1`: впишите
   `channel_id: <число>`, подставьте название в `title`. Ссылку-приглашение
   в файл **не вставляйте** — по ней может вступить любой.
6. В той же записи поменяйте `enabled: false` на `enabled: true` и запустите
   **Verify Sources** ещё раз — канал включится, как только проверка его прочитает.

Ещё один приватный канал — скопируйте запись `tg_private_1` под новым `id`.

## Шаг 8. Первый запуск: генерируем посты

1. **Actions** → слева **Collect & Generate** → **Run workflow** → **Run workflow**.
2. Через 3–7 минут вам в личку от бота придут **превью постов с кнопками**:

   ```
   ✅ Опубликовать   ✍️ Переписать
   🕒 Отложить       🗑 Отклонить
   ```

3. Нажмите **✅ Опубликовать** на том, который нравится.

Что делают кнопки:

| Кнопка | Что происходит |
|---|---|
| ✅ Опубликовать | пост выйдет в канал в свой слот (09:30 или 19:30 по Дубаю) |
| ✍️ Переписать | робот напишет по тем же фактам другой текст и пришлёт новое превью в ближайшие ~30 минут (следующий **Approve Poll**). Не больше трёх раз на один пост |
| 🕒 Отложить | пост получит следующий свободный слот и придёт на утверждение снова |
| 🗑 Отклонить | пост отменяется навсегда |

> Нажатие обрабатывается не мгновенно: робот проверяет кнопки раз в 30 минут
> (workflow **Approve Poll**), поэтому после нажатия кнопка может «крутиться»
> и ничего не показывать — это нормально, решение уже записано. Когда робот
> его применит, кнопки с превью исчезнут и придёт сообщение, что сделано.
> Если ждать не хочется — запустите его вручную:
> **Actions → Approve Poll → Run workflow**.

**Что сейчас в очереди.** Напишите боту «статус» — он ответит списком: что
одобрено и когда выйдет по Дубаю, что ждёт вашего решения, что переписывается.
После каждого нажатия кнопки приходит подтверждение с временем выхода.
Важно: «Переписать» после «Опубликовать» отменяет публикацию — новый вариант
нужно одобрить заново, об этом бот напишет.

**Поправить текст самой.** Ответьте (reply) на превью своим текстом — он
целиком заменит текст поста, картинка останется, и придёт новое превью с
кнопками. Ответ вида «переписать: короче и без цифр» — пожелание роботу: он
перепишет пост с учётом этой просьбы. Обычное сообщение боту без reply —
это материал в копилку (шаг 11), а не правка.

## Шаг 9. Первая публикация

Дальше всё идёт само: workflow **Publish** просыпается перед каждым слотом
(09:25 и 19:25 по Дубаю) и публикует то, что вы одобрили.

Хотите увидеть результат прямо сейчас — **Actions → Publish → Run workflow**.
Если время слота ещё не наступило, пост подождёт; это нормально.

Повторный запуск ничего не сломает: робот помнит, что уже опубликовал,
и дубля не сделает.

### Прислать боту свой материал

Увидели в Instagram интересный пост, получили от застройщика прайс или
планировку, сняли рилс — перешлите это боту в личку, как обычное сообщение.
Подходят: скриншот (фото), PDF, видео, пересланный пост из WhatsApp или
Telegram, просто текст. Подпись к файлу помогает: «планировка 2 спальни,
Creek Harbour» — и робот поймёт, о чём пост.

Что произойдёт: бот ответит «Сохранила», затем в ближайшие полчаса (пока
идёт опрос кнопок) прочитает текст со скриншота, вытащит текст из PDF,
расшифрует речь из видео и пришлёт вам превью поста с теми же кнопками
«Опубликовать / Переписать / Отложить / Отклонить». Если из материала пост
не складывается (личная заметка, пустая картинка), придёт короткое
«пост не сложился» — с причиной.

Для видео нужен секрет `OPENAI_API_KEY` (расшифровка идёт через Whisper).
Без него видео не читается, пост строится только по подписи. Файлы больше
20 МБ Telegram боту не отдаёт — сожмите или отправьте скриншотом.

## Запуск на своём компьютере (не обязательно)

Пригодится, чтобы посмотреть, как всё работает, не трогая канал.

```bash
git clone https://github.com/<ваш-логин>/news.git
cd news

python3 -m venv .venv          # отдельное окружение для зависимостей
source .venv/bin/activate      # на Windows: .venv\Scripts\activate
pip install --upgrade pip setuptools wheel
pip install -r requirements.txt

cp .env.example .env           # впишите в .env свои ключи (файл не попадёт в git)

make dry-run                   # полный прогон БЕЗ обращения в Telegram
make test                      # тесты
```

После `make dry-run` посмотрите:
- `out/drafts.json` — сгенерированные посты;
- `assets/generated/` — нарисованные карточки.

> `python -m venv` обязателен: без него установка `feedparser` на некоторых
> системах падает на сборке пакета `sgmllib3k`.

## Если не работает

`Connection error` / `Illegal header value` у Anthropic — в секрет попал не только
ключ, а весь пример команды с сайта (`curl … --header "x-api-key: …"`). Робот
умеет вытащить ключ из такого текста сам и напишет об этом в журнале, но лучше
перезаписать секрет `ANTHROPIC_API_KEY` одним значением `sk-ant-…`. То же
относится к `TELEGRAM_BOT_TOKEN` (только `1234567890:AA…`) и `TELEGRAM_OWNER_ID`
(только число).

**Превью не приходят в личку.**
Напишите боту `/start` в личку — Telegram запрещает боту писать первым.
Проверьте, что `TELEGRAM_OWNER_ID` — это именно ваш числовой id.

**Workflow падает красным крестиком.**
Откройте его в **Actions**, нажмите на упавший шаг, прочитайте последние строки.
Чаще всего это `Не заданы переменные окружения` — значит, пропущен секрет
из шага 6 (имя должно совпадать буква в букву).

**Бот не может опубликовать в канал.**
`Bad Request: chat not found` — неверный `TELEGRAM_CHANNEL_ID`.
`not enough rights` — бот не администратор или у него нет права публикации (шаг 3).

**Постов не генерируется.**
Скорее всего, ни один источник не включён. Вернитесь к шагу 7.
В логе **Collect & Generate** будет видно, сколько материалов собрано.

**Состояние не сохраняется, push падает.**
**Settings → Actions → General → Workflow permissions →
Read and write permissions** (шаг 5, пункт 4).

**Хочу остановить всё прямо сейчас.**
**Settings → Actions → General → Disable actions**. Ничего не сломается,
состояние сохранится.

## Безопасность в двух словах

- Ключи живут только в GitHub Secrets. В репозитории их нет — это проверяет
  автоматический тест `scripts/check_no_secrets.py` при каждом коммите.
- Если токен бота всё-таки утёк — @BotFather → `/revoke` → новый токен →
  обновите секрет `TELEGRAM_BOT_TOKEN`.
- В `state/` **нельзя** складывать телефоны, email и @username интересантов.
  Подробности — в `docs/SECURITY.md`.
