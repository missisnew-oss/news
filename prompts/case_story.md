# Рубрика: case_story — «История клиента»

RUBRIC_ID: {{rubric}}
TODAY: {{today}}
MAX_CHARS: {{max_chars}}

## Входные данные

Внутренние данные сделки, уже обезличенные. **Твоя задача — обезличить ещё раз
при написании.**

<INPUT_ITEMS>{{items}}</INPUT_ITEMS>

## Цель поста

Показать на реальном примере, как принимается решение: что хотел клиент, что
посчитали, почему выбрали не то, с чего начинали. Социальное доказательство
работы специалиста и одновременно обучающий материал.

Это продающая рубрика (учитывается в лимите 25% из `docs/CONTENT_STRATEGY.md`),
но продажа — только через демонстрацию процесса, не через результат.

## Структура

1. **Заголовок** — конфликт кейса, не «История клиента».
   Пример формы: «Когда „выгодный“ вариант оказался не тем».
2. **Запрос** — кто пришёл (обобщённо: «семья из СНГ», «резидент, живёт тут
   три года»), бюджет диапазоном, цель, горизонт.
3. **«Что хотели сначала»** — исходная гипотеза клиента. Обычно это
   распространённое заблуждение, в нём и ценность кейса.
4. **«Что посчитали»** — 3–4 буллета с арифметикой. Цифры из источника либо
   явно помеченные как условные.
5. **«Что выбрали и почему»** — решение и логика.
6. **«Что вышло»** — результат на сегодня, **без обещаний на будущее**.
7. **Вывод** — одно предложение-правило, применимое к читателю.
8. **CTA.**
9. **Хештеги.**

Дисклеймер о том, что это не инвестиционная рекомендация, добавляет код —
дописывать его самому не нужно.

## Длина

Целевая: 600–720 символов. Потолок: `{{max_chars}}`.

## CTA

Жёсткий, но через разбор, а не через объект:

- «Хотите такой же разбор под вашу ситуацию — три вопроса в боте.»
- «Пришлите свой платёжный план — разберу и покажу нагрузку по годам.»

## Изображение

- `image.mode`: `"card"`. **Никогда** фото клиента, фото конкретной квартиры
  или документов.
- `image.headline`: суть кейса, до 60 символов, без названия проекта и района,
  если район делает кейс узнаваемым.
- `image.accent`: ключевая цифра кейса, до 18 символов, только если она есть
  в `facts` и не деанонимизирует клиента. Иначе `""`.
- `image.stock_query`: `"two people discussing documents table neutral"`.

## Критичные self_check

- `no_guaranteed_returns` — **самый критичный флаг рубрики**. Кейс читается как
  обещание будущим клиентам. Запрещено: «клиент заработал X%», «за год выросло
  на Y%», «так будет и у вас». Разрешено: «денежный поток пошёл с первого месяца».
- `all_numbers_have_source` — критичен. Цифры сделки либо из источника, либо
  помечены `<i>(условно)</i>`.
- `fits_telegram_limit`.

## Персональные данные — жёсткое требование

Запрещено упоминать: имя, национальность точнее «из СНГ», профессию, возраст,
состав семьи детальнее слова «семья», номер юнита, этаж, название башни,
точную дату сделки, точную сумму (только диапазон).

Правило проверки: если комбинация деталей позволяет вычислить человека в круге
из 50 читателей — убери одну деталь.

## Чего не делать

- Не писать кейс без единой проблемы — читается как выдумка.
- Не подавать результат как воспроизводимый.
- Не называть застройщика в негативном ключе.
- Не публиковать кейс, если во входных данных нет отметки о согласии клиента.
- Эмодзи: максимум два, как маркеры абзацев.

## Формат ответа — строго валидный JSON

Верни ТОЛЬКО JSON-объект по схеме ниже. Без markdown-обёртки, без тройных
кавычек, без комментариев, без текста до или после. Первый символ ответа — `{`,
последний — `}`.

```json
{
  "rubric": "<rubric_id>",
  "title": "строка, не длиннее 90 символов, без markdown",
  "body": "строка, текст поста; разрешены только теги <b>, <i>, <a href=\"...\"> (Telegram HTML)",
  "hashtags": ["#дубай", "#недвижимость"],
  "cta": "строка, одна фраза призыва к действию",
  "image": {
    "mode": "card",
    "headline": "строка не длиннее 60 символов для фирменной карточки",
    "accent": "строка не длиннее 18 символов: цифра-акцент, либо пустая строка",
    "stock_query": "english keywords for Unsplash/Pexels fallback"
  },
  "sources": [{"source_id": "...", "title": "...", "url": "https://..."}],
  "facts": [
    {
      "claim": "...",
      "value": "...",
      "source_url": "https://...",
      "confidence": "confirmed | single_source | rumour",
      "sources": ["https://...", "https://..."]
    }
  ],
  "self_check": {
    "all_numbers_have_source": true,
    "no_guaranteed_returns": true,
    "language_is_russian": true,
    "no_verbatim_copy": true,
    "fits_telegram_limit": true
  },
  "length_chars": 0,
  "needs_separate_text": false
}
```

Обязательные условия по полям:
- `rubric` — ровно то значение, что пришло в `RUBRIC_ID` выше (`{{rubric}}`).
- `title` — до 90 символов, без markdown и без эмодзи.
- `body` — только теги `<b>`, `<i>`, `<a href="...">`; переносы строк как `\n`.
- `hashtags` — 2–4 штуки, строчными, по-русски, первым `#дубай`.
- `cta` — одна фраза; она же дублируется в конце `body`.
- `image.mode` — `"card"`, `"stock"` или `"press"` согласно разделу «Изображение».
- `image.headline` — до 60 символов; `image.accent` — до 18 символов или `""`.
- `image.stock_query` — на английском, 3–6 слов, заполняется всегда.
- `sources[].source_id` — идентификатор источника **ровно так, как он пришёл
  в поле `source_id` соответствующего элемента `<INPUT_ITEMS>`** (например
  `gulf_news_rss`, `dld_open_data_portal`). Не подставляй сюда название
  категории и не придумывай новых идентификаторов.
- `sources[].url` — только из `<INPUT_ITEMS>`; конструировать ссылки запрещено.
- `facts` — по одной записи на каждую цифру, встречающуюся в `body`;
  `confidence` — `confirmed`, `single_source` или `rumour` по правилам раздела
  «Проверка и маркировка» системного промпта; `sources` — все url из
  `<INPUT_ITEMS>`, где этот факт встречается (первый дублируется в `source_url`).
- `self_check` — честная самопроверка; `false` лучше, чем ложный `true`.
- `length_chars` — фактическая длина `body` в символах.
- `needs_separate_text` — `true`, если полный текст не помещается в
  `{{max_chars}}` и нужна вторая часть отдельным сообщением.
