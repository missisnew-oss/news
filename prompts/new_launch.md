# Рубрика: new_launch — «Новый лонч»

RUBRIC_ID: {{rubric}}
TODAY: {{today}}
MAX_CHARS: {{max_chars}}

## Входные данные

Единственный разрешённый источник фактов и цифр для этого поста:

<INPUT_ITEMS>{{items}}</INPUT_ITEMS>

Это официальный анонс застройщика или новость о старте продаж. **Всё, чего нет
внутри `<INPUT_ITEMS>`, в посте быть не может** — ни цен, ни дат, ни планировок,
ни названий башен.

Если во входных данных нет как минимум названия проекта, района и одного
параметра входа (цена или план оплаты) — не достраивай недостающее. Сформируй
короткий `body`-черновик по имеющимся данным и выставь
`self_check.all_numbers_have_source: false`, чтобы код отправил пост на доработку.

## Цель поста

Познакомить с проектом и **собрать заявки в приоритетный список**. Это главная
конверсионная рубрика канала.

Пост должен читаться как разбор, а не как реклама. Механизм доверия — блок
«кому не подойдёт».

## Структура

1. **Заголовок:** «Новый лонч: {название проекта}» либо более конкретно, если
   есть яркий параметр («Лонч с рассрочкой после ключей: {проект}»).
2. **Карточка проекта** — компактный список, только из источника:
   застройщик, район, тип юнитов, вход от, план оплаты, handover, старт продаж.
   Отсутствующие параметры просто не упоминай.
3. **«Кому подойдёт»** — 1–2 предложения. Под какую задачу покупателя.
4. **«Кому не подойдёт»** — 1–2 предложения. Обязательный блок. Честный минус:
   срок ожидания, отсутствие дохода до handover, район в стройке, высокий
   service charge.
5. **Механика лонча** — короткое объяснение, почему подавать интерес надо
   заранее: порядок подачи влияет на доступные планировки. Без давления
   и без обещаний конкретного юнита.
6. **CTA** — жёсткий, единственный в посте.
7. **Ссылка на источник** — официальный анонс.
8. **Хештеги** — включая район, если он известен.

## Длина

Целевая: 500–600 символов под фото. Потолок: `{{max_chars}}`.
Если параметров проекта много — оставь в посте 5–6 ключевых, поставь
`needs_separate_text: true` и вынеси остальное во второе сообщение.

## CTA

Жёсткий, с одним действием. Формулировки:

- «Хотите в приоритетный список по этому проекту — нажмите кнопку ниже, бот
  задаст три вопроса: бюджет, срок, цель.»
- «Заявка-интерес — по кнопке. Пришлю материалы за несколько дней до старта.»

Запрещено: «пишите в личку», «успейте», «осталось N юнитов» (если N нет
в источнике), «гарантирую лучший юнит».

## Изображение

- `image.mode`: `"press"` — пресс-материал застройщика из входных данных.
  Если пресс-материала нет — `"card"`. **Никогда не бери чужие рендеры.**
- `image.headline`: название проекта и район, до 60 символов, без эмодзи.
- `image.accent`: порог входа или срок handover, до 18 символов, только если
  эта цифра есть в `facts`. Иначе `""`.
- `image.stock_query`: `"dubai new residential development construction"` или
  с указанием района из источника.

## Критичные self_check

- `all_numbers_have_source` — **самый критичный флаг рубрики**. Цена, дата
  handover, план оплаты — типовые места галлюцинаций.
- `no_guaranteed_returns` — критичен. Ни слова про будущий рост цены проекта.
- `no_verbatim_copy` — критичен. Пресс-релизы копируются особенно легко.
- `fits_telegram_limit`.

## Чего не делать

- Не выдумывать названия башен, фаз, планировок, отделки.
- Не писать «лучший проект года», «уникальная локация».
- Не создавать срочность, которой нет в источнике.
- Не ссылаться на «вчерашний лонч», если его нет во входных данных.
- Не обещать доступность конкретного юнита.

## Формат ответа — строго валидный JSON

Верни ТОЛЬКО JSON-объект по схеме ниже. Без markdown-обёртки, без тройных
кавычек, без комментариев, без текста до или после. Первый символ ответа — `{`,
последний — `}`.

```json
{
  "rubric": "<rubric_id>",
  "title": "строка, не длиннее 90 символов, без markdown",
  "body": "строка, текст поста; разрешены только теги <b>, <i>, <a href=\"...\"> (Telegram HTML)",
  "hashtags": ["#дубай", "#недвижимость"],
  "cta": "строка, одна фраза призыва к действию",
  "image": {
    "mode": "card",
    "headline": "строка не длиннее 60 символов для фирменной карточки",
    "accent": "строка не длиннее 18 символов: цифра-акцент, либо пустая строка",
    "stock_query": "english keywords for Unsplash/Pexels fallback"
  },
  "sources": [{"source_id": "...", "title": "...", "url": "https://..."}],
  "facts": [
    {
      "claim": "...",
      "value": "...",
      "source_url": "https://...",
      "confidence": "confirmed | single_source | rumour",
      "sources": ["https://...", "https://..."]
    }
  ],
  "self_check": {
    "all_numbers_have_source": true,
    "no_guaranteed_returns": true,
    "language_is_russian": true,
    "no_verbatim_copy": true,
    "fits_telegram_limit": true
  },
  "length_chars": 0,
  "needs_separate_text": false
}
```

Обязательные условия по полям:
- `rubric` — ровно то значение, что пришло в `RUBRIC_ID` выше (`{{rubric}}`).
- `title` — до 90 символов, без markdown и без эмодзи.
- `body` — только теги `<b>`, `<i>`, `<a href="...">`; переносы строк как `\n`.
- `hashtags` — 2–4 штуки, строчными, по-русски, первым `#дубай`.
- `cta` — одна фраза; она же дублируется в конце `body`.
- `image.mode` — `"card"`, `"stock"` или `"press"` согласно разделу «Изображение».
- `image.headline` — до 60 символов; `image.accent` — до 18 символов или `""`.
- `image.stock_query` — на английском, 3–6 слов, заполняется всегда.
- `sources[].source_id` — идентификатор источника **ровно так, как он пришёл
  в поле `source_id` соответствующего элемента `<INPUT_ITEMS>`** (например
  `gulf_news_rss`, `dld_open_data_portal`). Не подставляй сюда название
  категории и не придумывай новых идентификаторов.
- `sources[].url` — только из `<INPUT_ITEMS>`; конструировать ссылки запрещено.
- `facts` — по одной записи на каждую цифру, встречающуюся в `body`;
  `confidence` — `confirmed`, `single_source` или `rumour` по правилам раздела
  «Проверка и маркировка» системного промпта; `sources` — все url из
  `<INPUT_ITEMS>`, где этот факт встречается (первый дублируется в `source_url`).
- `self_check` — честная самопроверка; `false` лучше, чем ложный `true`.
- `length_chars` — фактическая длина `body` в символах.
- `needs_separate_text` — `true`, если полный текст не помещается в
  `{{max_chars}}` и нужна вторая часть отдельным сообщением.
