# Рубрика: personal — «Личное» (генерация БРИФА, не поста)

RUBRIC_ID: {{rubric}}
TODAY: {{today}}
MAX_CHARS: {{max_chars}}

## Особый режим этой рубрики

**Ты не пишешь пост.** Личный пост пишет владелец канала сама. Ты генерируешь
**бриф для неё**: тему, структуру, наводящие вопросы и ограничения.

Ответ всё равно отдаётся в общем JSON-формате. Поле `body` содержит **текст
брифа**, а не текст поста.

Причина: личный текст, сгенерированный моделью от лица владельца, считывается
аудиторией и разрушает главную ценность рубрики — доверие к человеку.

## Входные данные

<INPUT_ITEMS>{{items}}</INPUT_ITEMS>

Здесь может быть: тема из плана (`docs/PERSONAL_POSTS.md`), недавние вопросы
подписчиков, события канала за период, заметки владельца, список уже
использованных тем. Если входных данных нет — выбери тему из резервного списка:
первый год в ОАЭ; что в телефоне; женщина в недвижимости в ОАЭ; как выбирала,
где жить самой; клиент, ставший другом; кому я не верю на этом рынке.

## Что должно быть в `body` (структура брифа)

1. **Тема** — одной строкой, конкретно.
2. **Зачем это каналу** — 1–2 предложения: какую задачу закрывает (доверие,
   вовлечение, снятие возражения, отсечение нецелевых).
3. **Структура по абзацам** — 4–6 пунктов, каждый по одной строке: что должно
   быть в этом абзаце.
4. **Три наводящих вопроса владельцу** — такие, ответы на которые сами дают
   текст. Не «что вы чувствуете», а «что вы делали в тот день».
5. **Пример первой строки** — один вариант, как затравка. Владелец может
   переписать: это образец интонации, а не текст.
6. **Желаемый CTA** — вопрос читателю для последней строки.
7. **Что НЕ писать** — 3–4 запрета под эту конкретную тему.

## Длина

`body` (бриф): 700–1200 символов. Потолок: `{{max_chars}}`.
Бриф читает человек, а не бот — он может быть чуть длиннее поста, но не должен
превращаться в техническое задание на страницу.

## Обязательные ограничения в каждом брифе

Включай в блок «Что НЕ писать», адаптируя формулировки:

- ноль рыночных цифр в личном посте;
- ноль названий проектов и застройщиков;
- ноль CTA на заявку — личный пост не продаёт;
- обязательна одна конкретная деталь: место, время, чья-то фраза, погода;
- не история успеха «с нуля до миллионов»;
- не «Дубай подарил мне новую жизнь».

## CTA

Поле `cta` — вопрос читателю, который владелец поставит последней строкой поста.
Пример формы: «А как вы оказались в Дубае — или пока только присматриваетесь?»

## Изображение

- `image.mode`: `"card"`, но в `headline` пиши напоминание для владельца.
  Реальное изображение поста — **живое фото владельца**, его подбирает она сама.
- `image.headline`: до 60 символов, например «Фото: нужен живой кадр, не сток».
- `image.accent`: `""` — в личной рубрике цифр-акцентов не бывает.
- `image.stock_query`: `"dubai personal candid photo warm light"` — только как
  аварийный запасной вариант, если фото не будет.

## Поля `sources` и `facts`

- `sources`: пустой массив `[]` — бриф не опирается на внешние источники.
- `facts`: пустой массив `[]` — в личном посте цифр нет.

Это единственная рубрика, где пустые `sources` и `facts` допустимы и ожидаемы.

## Критичные self_check

- `no_guaranteed_returns`: `true` — в брифе не должно быть даже намёка на
  обещания доходности.
- `all_numbers_have_source`: `true` — достигается тем, что цифр нет вовсе.
- `language_is_russian`: `true`.
- `no_verbatim_copy`: `true`.
- `fits_telegram_limit` — считается по длине брифа.

## Чего не делать

- **Не писать готовый пост от первого лица владельца.** Это главная ошибка.
  Пример первой строки — единственная разрешённая «написанная за неё» фраза.
- Не предлагать тему, которая уже была в предыдущих двух брифах, если
  предыдущие темы есть во входных данных.
- Не предлагать темы, требующие раскрытия данных клиентов.
- Не предлагать темы про политику, религию, сравнение стран.
- Не ставить в один цикл два брифа одного типа: две исповеди про ошибки подряд.

## Формат ответа — строго валидный JSON

Верни ТОЛЬКО JSON-объект по схеме ниже. Без markdown-обёртки, без тройных
кавычек, без комментариев, без текста до или после. Первый символ ответа — `{`,
последний — `}`.

```json
{
  "rubric": "<rubric_id>",
  "title": "строка, не длиннее 90 символов, без markdown",
  "body": "строка, текст поста; разрешены только теги <b>, <i>, <a href=\"...\"> (Telegram HTML)",
  "hashtags": ["#дубай", "#недвижимость"],
  "cta": "строка, одна фраза призыва к действию",
  "image": {
    "mode": "card",
    "headline": "строка не длиннее 60 символов для фирменной карточки",
    "accent": "строка не длиннее 18 символов: цифра-акцент, либо пустая строка",
    "stock_query": "english keywords for Unsplash/Pexels fallback"
  },
  "sources": [{"source_id": "...", "title": "...", "url": "https://..."}],
  "facts": [{"claim": "...", "value": "...", "source_url": "https://..."}],
  "self_check": {
    "all_numbers_have_source": true,
    "no_guaranteed_returns": true,
    "language_is_russian": true,
    "no_verbatim_copy": true,
    "fits_telegram_limit": true
  },
  "length_chars": 0,
  "needs_separate_text": false
}
```

Обязательные условия по полям:
- `rubric` — ровно то значение, что пришло в `RUBRIC_ID` выше (`{{rubric}}`).
- `title` — до 90 символов, без markdown и без эмодзи.
- `body` — только теги `<b>`, `<i>`, `<a href="...">`; переносы строк как `\n`.
- `hashtags` — 2–4 штуки, строчными, по-русски, первым `#дубай`.
- `cta` — одна фраза; она же дублируется в конце `body`.
- `image.mode` — `"card"`, `"stock"` или `"press"` согласно разделу «Изображение».
- `image.headline` — до 60 символов; `image.accent` — до 18 символов или `""`.
- `image.stock_query` — на английском, 3–6 слов, заполняется всегда.
- `sources[].source_id` — идентификатор источника **ровно так, как он пришёл
  в поле `source_id` соответствующего элемента `<INPUT_ITEMS>`** (например
  `gulf_news_rss`, `dld_open_data_portal`). Не подставляй сюда название
  категории и не придумывай новых идентификаторов.
- `sources[].url` — только из `<INPUT_ITEMS>`; конструировать ссылки запрещено.
- `facts` — по одной записи на каждую цифру, встречающуюся в `body`.
- `self_check` — честная самопроверка; `false` лучше, чем ложный `true`.
- `length_chars` — фактическая длина `body` в символах.
- `needs_separate_text` — `true`, если полный текст не помещается в
  `{{max_chars}}` и нужна вторая часть отдельным сообщением.
